# Project Structure

This document describes the project organization and where to add new files.

## Current Structure

```
agent-digital-twin/
├── src/                          # All source code
│   ├── agent/                    # Core agent logic
│   │   ├── evaluator.py          # Message evaluation
│   │   └── handlers.py           # Response handlers
│   ├── tools/                    # Agent tools
│   │   └── tools.py              # Email recording, logging, notifications
│   ├── context/                  # Context & prompts
│   │   └── context.py            # System prompts, LinkedIn/summary loading
│   └── ui/                       # User interfaces
│       └── styles.py             # CSS/JS styling for Gradio
│
├── tests/                        # All tests (mirrors src structure)
│   └── test_evaluator.py         # Evaluator tests
│
├── data/                         # Data files
│   ├── linkedin.pdf              # LinkedIn profile
│   ├── summary.txt               # Personal summary
│   └── emails.txt                # Generated by tools
│
├── planning/                     # Project planning
│   ├── README.md                 # Planning guide
│   ├── STATUS.md                 # Current status
│   ├── ROADMAP.md                # Implementation roadmap
│   └── STRUCTURE.md              # This file
│
├── app.py                        # Main entry point (Gradio app)
├── .env                          # Environment variables
├── .env.example                  # Example environment variables
└── README.md                     # Project README
```

## Where to Add New Files

### Agent Logic (Phase 2+)
- **Routing**: `src/agent/router.py`
- **Memory**: `src/agent/memory.py` or new `src/memory/` package
- **Coordinator**: `src/agent/coordinator.py`

### Integrations (Phase 3+)
Create `src/integrations/` when adding:
- Telegram bot: `src/integrations/telegram.py`
- Other messaging platforms
- External APIs

### Additional Tools
Add to `src/tools/`:
- New tool functions
- Tool utilities

### Guardrails (Phase 5+)
Create `src/guardrails/` when adding:
- Input validation
- Output validation
- Safety checks

### Utilities
Create `src/utils/` when needed for:
- Configuration management
- Logging utilities
- Shared helpers

### Tests
Mirror the `src/` structure in `tests/`:
- Test for `src/agent/router.py` → `tests/test_router.py`
- Test for `src/integrations/telegram.py` → `tests/test_telegram.py`
- Test fixtures go in `tests/fixtures/`

### Documentation
Add to `docs/` directory (create when needed):
- Architecture docs
- API documentation
- Deployment guides

## Import Patterns

When importing within the project, use absolute imports from the project root:

```python
# ✅ Correct
from src.agent.evaluator import evaluate_message
from src.tools.tools import log_evaluation
from src.context.context import TWIN_SYSTEM_PROMPT

# ❌ Avoid relative imports between packages
from ..tools.tools import log_evaluation  # Don't do this
```

## Principles

1. **Domain-based organization**: Group by functionality (agent, tools, integrations)
2. **Tests mirror source**: Same structure as `src/` for easy navigation
3. **Separation of concerns**: Code, data, docs, and planning are separate
4. **Scalable**: Easy to add new modules without cluttering root

## Future Considerations

As the project grows, we may:
- Split large modules into sub-packages (e.g., `src/agent/` → `src/agent/evaluation/`, `src/agent/routing/`)
- Add `scripts/` for utility scripts
- Add package configuration (`setup.py` or `pyproject.toml`) if publishing
- Add CI/CD configuration (`.github/workflows/`)
